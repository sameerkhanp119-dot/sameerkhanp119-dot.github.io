commerce-order-platform

Order and payment microservices that stay consistent without distributed transactions. An order is accepted, payment is attempted, and the order is either confirmed or cancelled, coordinated through Kafka with a choreography saga.

  • No lost or phantom eventsA transactional outbox writes each event in the same database transaction as the order, then relays it to Kafka.

  • Failures compensate cleanlyA declined payment cancels the order automatically; poison messages go to a dead-letter topic instead of blocking a partition.

How I work

The habits teams have told me they value most.

Design for the failure case first

Every network call can time out and every message can arrive twice. I make that explicit in the design instead of finding it in production.

Make it observable

Metrics, structured logs and alerts ship with the feature, so on-call engineers can answer “what happened” in minutes.

Leave it simpler than I found it

Clear module boundaries, honest naming and tests that describe behavior make the next change cheaper.

Raise the team

I review code to teach, write the design doc before the code, and pair on the hard parts.
